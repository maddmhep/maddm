# MadDM

**CosmiXsPPPC Earth fluxes and shared halo:** see [installation, settings, outputs and changed files](CHANGES_COSMIXSPPPC_SHM.md), [RAPIDD velocity-profile selection](docs/HALO_VELOCITIES.md), and the [implementation note](docs/indirect_detection_notes.pdf).


MadDM is a numerical tool designed to compute dark matter relic abundance, dark matter nucleus scattering rates, and dark matter indirect detection predictions in a generic model.  
Based on the existing MadGraph 5 architecture, MadDM is easily integrable into any MadGraph collider study. The tool features a simple Python interface, maintaining the user-friendliness characteristic of MadGraph 5 without sacrificing functionality.

## Installation

**MadDM** is a plugin for `MG5_aMC@NLO` (**MadGraph**). To install it and run it, follow the steps below:

1.  Start MadGraph and type the following in the command line:

    ``` text
    MG5_aMC> install maddm
    ```

2.  Exit MadGraph and run MadDM with:

    ``` bash
    ./maddm.py
    ```

### Requirements

- At least MadGraph v3.6 is required to run the latest version of MadDM.
- MadDM is compatible with the LTS version of MadGraph.
- MadDM requires:
   -   Python 3.6+
   -   Fortran
   -   `numpy`
   -   `scipy` (required for some recent features)
   -   cmake
- It supports Python 2.7, but it requires the installation of the `six` package.

### Running relic density, direct and indirect detection together

After importing your model and defining its dark matter candidate, generate
the processes for all the calculations you want in the same output:

```text
generate relic_density
add direct_detection
add indirect_detection
output dm_combined
launch dm_combined
```

At the launch menu, `1` toggles relic density and `4` cycles through the
continuum indirect modes. You can also enter `relic = ON` and
`indirect = sigmav` for rates, or `indirect = flux_earth` for the propagated
CosmiXsPPPC antiproton and antideuteron predictions. For a gamma-ray line
analysis, also run `add indirect_spectral_features` before `output`.

If the menu shows **No processes generated**, add the missing process at
the main MadDM prompt and export a new output directory. Use `add` to keep
the processes already in memory; `generate` starts a new set. Installing
RAPIDD enables the nucleon recoil calculation but does not generate relic
or indirect matrix elements. Existing cards can be reused: the obsolete
`indirect_flux_earth_method` setting is ignored when they are read.

## Overview

MadDM can calculate the dark matter relic abundance in models that include a multi-component dark sector, resonance annihilation channels, and co-annihilations.

### Direct Detection Module

The Direct Detection module of MadDM computes spin-independent and spin-dependent cross-sections, as well as differential recoil rates, for both dark matter–nucleon and dark matter–electron scattering. It then evaluates the statistical significance of the selected model against the most recent experimental data.

For dark matter–nucleon scattering, the RAPIDD code is used to calculate the differential recoil rates for xenon, argon, and germanium targets. Subsequently, it computes the expected signal in xenon and determines the p-value of the input model by employing the likelihood function derived from the 2024 LZ results.

For dark matter–electron scattering, the module evaluates both the differential recoil spectrum and the event rate as a function of the scintillation signal in xenon. The p-value is then calculated using the likelihood functions obtained from the XENON10 and XENON1T S2-only analyses.

### Indirect Detection Module

The indirect detection module of MadDM computes the velocity-averaged cross-section for dark matter particles annihilating into multiple final state particles. It further provides the energy spectra of photons, neutrinos, and cosmic rays generated by these final states after decaying, showering, and hadronization. The module automatically computes the flux of prompt neutrinos and gamma rays at detection.

In `flux_earth` mode, it computes antiproton and antideuteron fluxes with the bundled CosmiXsPPPC propagated annihilation tables and secondary spectra. Positron Earth fluxes are pending the corresponding inputs. A built-in interface with the **nested sampling** PyMultiNest algorithm enables efficient sampling of the model parameter space. The code also allows testing the model against the Fermi-LAT dwarf spheroidal galaxy likelihood.

MadDM is also able to compute loop-induced processes relevant to indirect detection phenomenology. Specifically, MadDM can automatically compute the annihilation of dark matter into final states like gamma-gamma, gamma-Z, gamma-H, gluon-gluon, and others. In generic dark matter models, these final states are loop-induced processes, where the tree-level amplitude is zero.

For the gamma-ray line final state, MadDM performs an analysis of the signal against Fermi-LAT gamma-ray line data to assess whether the model parameter space is allowed by current exclusion limits at 95% CL.

### Reading a run directory

Open `output/<run>/README.md` for a guide to the files produced in that
run, and `MadDM_results.txt` for the physics summary. With Matplotlib
installed, MadDM writes `DDrates.pdf` alongside the nuclear recoil rate
table and `source_spectra.pdf` for the source yields available from the
selected backend. Source spectra require `indirect = flux_source` or
`indirect = flux_earth`; `sigmav` computes rates only. The plots use log
axes and omit species or targets with no positive yield or rate. For
parameter scans, plots follow the `save_output` retention setting.

| `save_output` | What a scan retains for each point |
| --- | --- |
| `off` | `MadDM_results.txt`, `maddm.out`, `README.md`, and JSON summaries for applicable analyses. No spectra, recoil tables, PDFs, or raw event samples are retained. |
| `spectra` | The summaries plus available indirect spectra, flux tables, and enabled indirect plots. No detailed recoil files or raw LHE samples. |
| `all` | Full output, including available recoil tables and plots, indirect spectra and plots, and generated event samples. |

These modes do not change the scalar limits or fits written to the scan
table. The setting applies to scans; single-point runs retain full output.

MadDM writes `MadDM_results.txt` for every completed scan point, including
with `save_output = off`. It also copies both scripts in [`plotting/`](plotting/README.md)
to the parent `output/` directory, alongside the scan table. Existing copies
there are kept so local edits are preserved. For source multiplicities, use
a flux scan with `save_output = spectra` or `all`.

With `set fast` (`sigmav_method = inclusive`), the combined Fermi-LAT dwarf
likelihood defaults to the ten highest nominal J factors in the installed
dwarf data. Set `fermi_fast_dwarfs = all` in `maddm_card.dat`, or enter
`set fermi_fast_dwarfs all` in the launch menu, for the full sample. The
precise mode continues to use all 55 dwarfs. The combined limit and both
model likelihoods use the same sample, recorded in `Fermi_dSph_limits.json`.
The setting applies to spectrum-based likelihoods; rate-only `sigmav` runs
continue to use the precomputed channel limits.

## AMS-02 antiproton upper limits

This package adds model-specific two-body annihilation limits using bundled CosmiXsPPPC QUAINT-MED/NFW antiproton fluxes, with secondary normalization, slope and solar modulation profiled. It computes separate Milky Way partial rates and reports full-density and thermal-density exclusions. See [README_AMS02_PBAR.md](README_AMS02_PBAR.md) for installation, fresh-output generation, settings, validation and input assumptions.

Some third-party packages can be installed using the `install` command in the shell. Be sure to cite them as indicated during the install phase if you use them.

DM-nucleon direct detection uses [RAPIDD](https://github.com/cheekyparticle/RAPIDD_for_DM).
This distribution includes the RAPIDD source. MadDM builds it locally when
needed, both when generating direct detection and when launching an existing
run with nucleon direct detection enabled. It checks that the active Python
can import the wrapper and load the native library before using it. To force
a fresh build, run `install RAPIDD` in the MadDM shell. You need CMake, a C
compiler, and the GSL headers and libraries (`conda install -c conda-forge cmake gsl`
in a Conda environment). Git is needed only if the RAPIDD source is missing.
On macOS, MadDM builds for the active Python process's architecture, so use
GSL for that same architecture. If macOS rejects the newly built library
under Library Validation, run MadDM with a Python environment that allows
locally built native libraries.

The AMS-02 addition also reports antideuteron event forecasts from the
propagated CosmiXs Dbar table and saves an antiproton comparison PDF after
successful flux fits. See [README_AMS02_DBAR.md](README_AMS02_DBAR.md) for
the sensitivity prescription, settings and output files.
